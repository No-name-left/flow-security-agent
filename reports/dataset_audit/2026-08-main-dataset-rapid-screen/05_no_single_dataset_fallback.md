# 无合格单一主数据集时的替代路线分析

本文件只比较备选路线，不启动任何采集、重构或实验，也不修改正式研究计划。

| 路线 | 工作量 | 科学可信度 | 对现有论文口径的影响 | Unknown / few-shot 支撑 | 最大风险 |
|---|---|---|---|---|---|
| A. 严格多数据集 Benchmark Suite | 中等 | 中等到高；前提是每个结论只在自身数据集内成立 | 由“单一主数据集统一验证”改为“不同数据集分别回答不同问题” | 可分别承担，但不能声称同一数据同时解决 Unknown 与 few-shot | 容易被误写成跨库拼接；标签和输入语义不可直接比较 |
| B. 基于官方 run/step 的行为级重构 | 高 | 若官方 run/step 和时间边界完整则高 | 样本单位由 Flow 改为网络行为 Episode，但仍属网络行为研究 | 只有 run 数足够时才支持 10+1；本轮候选普遍缺少该证明 | 宽时间窗广播、背景污染和人工映射会重新制造标签问题 |
| C. 最小化受控补充采集 | 中到高 | 最高；可预注册 run、support/query、背景和标签链路 | 保持网络行为研究，但公开数据不再独自承担全部主实验 | 可直接保证每个选定类 11–13 个独立 run，最适合 U_final 与 1/5/10-shot | 环境搭建、攻击安全边界、复现和时间成本 |

## 推荐

若必须在 A/B/C 中选择一条解决本轮暴露的结构性缺口，优先推荐 **Fallback C：最小化受控补充采集**。原因是当前最难由公开数据补齐的不是类别名称，而是可审计的 10 个独立 support run、独立 query run、准确时间边界和背景流量控制。有限采集只补 U_final 与 few-shot 所需的少量网络行为类，不重造完整大数据集，也不把多个不合格数据集拼成一个“主数据集”。

Fallback A 可作为论文范围调整后的次选，但需要明确不同数据集分别承担开放集、few-shot 或跨域问题，不能形成单一统一主实验。Fallback B 只有在未来获得官方 run/step manifest 时才值得启动；在当前证据条件下，重构很可能仍无法满足 G5/G7。

## 启动前置条件

任何 fallback 均需另行评审和批准。特别是 C，应先冻结类别、每类 11–13 次独立执行、参数/主机/时间变化、Benign 并发、run ID、PCAP、步骤日志和安全隔离方案；本轮不实施。
