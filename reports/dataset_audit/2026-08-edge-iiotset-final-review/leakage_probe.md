# 泄漏与数据捷径轻量诊断

## 明确禁止的输入

正式模型禁止直接使用标签、文件名/路径、capture 名、原始 split、攻击脚本标识、固定攻击者/受害者 IP、绝对时间、唯一设备 ID 和 IDS 结果。原始 Payload、完整 URI/DNS/MQTT 字符串默认禁用；端口和小型应用层类别字段需单独消融。

## ML CSV 诊断结果

在作者 ML CSV 的 157,800 行上发现 814 个完全重复行（0.516%），去重后固定抽取 80,000 行，仅用 60 棵浅随机森林做泄漏探针：

| 输入/划分 | Accuracy | Macro-F1 | 解释 |
|---|---:|---:|---|
| shortcut-only，随机行切分 | 99.83% | 99.82% | IP、绝对时间、端口、URI/topic/DNS 类别编码和 Payload 长度足以近乎直接识别类别 |
| 行为数值 + 端口，随机切分 | 94.11% | 90.53% | 端口仍提供强场景信号 |
| 去端口行为数值，随机切分 | 73.77% | 69.83% | 去掉明显捷径后仍有可学习信号，但显著下降 |
| 去端口行为数值，端点对分组 | 24.28% | 9.10% | 跨端点泛化急剧下降；该分组还缺一个测试类，只作风险诊断 |

这不是正式传统模型基线，也不能用来比较研究方法。它只说明随机行切分会严重虚高，并确认去除明显捷径后并非完全无信号。

## 其他结构性风险

- 14 个攻击 CSV/PCAP 分别只含一个攻击类，捕获文件与标签一一对应；同一攻击类通常没有多个独立 run。
- MITM 原始 CSV 的 1,229 行中，代表性检查发现 1,135 个完全重复行且时间为 0；必须专门去重。
- 端点、端口、设备协议和应用字符串可能只在固定类别出现；随机 session 切分仍会共享同一攻击活动。
- 60 秒上下文可能编码捕获密度和固定攻击时段。
- 作者 ML/DNN CSV 是整理结果，缺少 capture/run 标识，不能作为正式无泄漏划分的唯一来源。

## 下一步必要证据

必须从原始 PCAP 重建 session，先按 capture/活动/时间块冻结 split，再去重和建上下文。由于攻击类通常只有一个 capture，这一数据集无法单独提供理想的同类跨 run 验证；最终主数据集锁定前，需要决定是将其定位为 class-held-out/少样本受控基准，还是用第二数据集承担跨场景验证。随机切分结果不得成为论文主结论。
