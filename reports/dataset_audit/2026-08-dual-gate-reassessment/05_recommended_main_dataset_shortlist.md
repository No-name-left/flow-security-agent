# 正式主数据集候选与排序

## 推荐的三个正式主候选

| 排名 | 数据集 | 能支撑什么 | 不能支撑什么 |
| --- | --- | --- | --- |
| 1 | CICIoMT2024 | 18 个网络攻击细类、5 个粗类、Benign；样本级已知类训练、类级 Unknown、1/5/10-shot、RAG/Reviewer；原始 PCAP 可用于统一重提取 | 在没有 run manifest 前，不能声称 activity-level few-shot 或严格跨运行泛化；官方 10/100 包窗口不能直接当作无捷径输入 |
| 2 | DataSense 2025 | 49 个攻击细类、7 个粗类与 Benign；可从网络 PCAP 构造广覆盖开放集，并研究近/远 Unknown 和知识卡 | 在核心归档未检查前，不能声称逐 Flow 精确标签、活动级 group split 或无需 Adapter；传感器证据不能偷渡进 Flow-only 主结果 |
| 3 | X-IIoTID | 18 细类/9 粗类、样本量大、三层标签；冻结网络列后可做样本级开放识别、SFT 与 Reviewer 对照 | 不能使用主机/应用/资源/IDS 泄漏列；缺少官方 run manifest，不能把样本级 few-shot 写成独立攻击活动适配 |

推荐执行顺序不是直接下载全部大文件，而是对三者各做一个小型“归档清单 + schema + 标签列 + 最小类计数 + 网络字段白名单”探针。第一份探针通过即冻结主数据，第二、三名保留为替代或外部验证。

## 五个重点数据集的相对排序

1. **CICIoMT2024**：网络输入最直接、18 类达到优选规模、PCAP/CSV 均有；主要代价是窗口和 run 审计。
2. **DataSense 2025**：类别最丰富，network-only 路线成立，但注册后归档结构和 Flow 化规则仍需核验。
3. **X-IIoTID**：标签与记录量充足，获取成本低；最大的科学风险是多源字段与纯网络语义混淆。
4. **UWF**：唯一具有直接逐 Flow ATT&CK 父 Technique 优势，但可靠可观察类和来源/端口捷径限制较强，更适合 ATT&CK 辅助实验。
5. **CICIoT2023**：最低门槛证据最完整之一，但单实验/类别与 10/100 包窗口使强结果很容易被解释为数据集捷径。

## 备用与辅助数据角色

- Gotham 2025：纯网络、类别足够，若能用攻击事件元数据去除跨设备副本，可升为正式备选。
- GeNIS：10 类窄范围且多窗口，适合作为干净的 pipeline 先导数据或消融集。
- NF-ToN-IoT-v3：适合验证大规模 NetFlow 接口和窄范围家族开放集，不适合作为丰富细类主任务。
- TQH-C2：不做主细类数据；可做 C2 检测器的跨 TLS/QUIC/HTTP profile 鲁棒性扩展。

## CSTNET 是否值得继续追踪

不建议继续作为恶意 Flow 主数据集投入。[IEEE DataPort/DataCite 官方元数据](https://api.datacite.org/dois/10.21227/4394-fv34)将其用途写为加密流量的 OTT/应用签名识别，未给出 Benign + 攻击细类、逐类计数或攻击标签格式；近期流量论文也把 CSTNET-TLS1.3 作为网站/应用分类数据。若未来研究转向通用流量表征预训练，可以重新考虑；对当前任务只保留一条文献说明即可。
